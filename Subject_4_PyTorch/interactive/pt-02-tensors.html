Tensors — the data structure of deep learning

Every input, weight, activation and gradient in PyTorch is a tensor. Most bugs you will ever debug are shape, dtype or device bugs — so this module goes deep: create, compute, broadcast, index, reshape, and understand exactly when memory is shared.

What is a tensor? Must-know

A tensor is an n-dimensional grid of numbers of one dtype, living on one device.

0-D scalar
a loss value — torch.tensor(3.14), shape ()
1-D vector
a bias, one sample's features — shape (784,)
2-D matrix
a batch of tabular samples, a Linear weight — shape (64, 784)
3-D
a batch of sequences — (batch, seq_len, features)
4-D
a batch of images — (N, C, H, W), e.g. (32, 3, 224, 224)

Four attributes describe any tensor, and you should check them constantly: x.shape, x.dtype, x.device, x.requires_grad.

Every element has the same dtype

The dtype decides precision, memory and which operations are allowed. Most deep-learning bugs here come from two places: NumPy defaulting to float64, and losses that insist on long class labels.

Element-wise, reductions and matrix multiplication

  • Element-wise — + - * / **, torch.exp, torch.sqrt, torch.clamp, torch.sigmoid: same shape in, same shape out.
  • Reductions — sum, mean, std, max, min, argmax, prod: collapse one or more dimensions. The dim argument names the axis that disappears. Must-know
  • Matrix multiplication — @ / torch.matmul: inner dimensions must match, (n, m) @ (m, p) → (n, p). This is what every Linear layer does. Must-know

Broadcasting: operate on different shapes without copying Must-know

  1. Align the shapes on the right. Missing leading dimensions count as 1.
  2. For each dimension the sizes must be equal, or one of them must be 1.
  3. Size-1 dimensions are stretched to match. The result takes the larger size in every position.

That is why logits + bias works for (64, 10) + (10,): the bias is reused for every sample in the batch.

Indexing works like NumPy

Use x[row, col], slices start:stop:step, negative indices, lists of indices and boolean masks. Basic slices return views (shared memory); lists and masks return copies.

Shape is just a way of reading flat memory Must-know

A tensor's data sits in one flat block (its storage). The shape and strides say how to read it: stride (4, 1) means "jump 4 elements for the next row, 1 for the next column".

  • view / reshape / unsqueeze / squeeze / flatten change the shape — usually without touching memory.
  • transpose / permute / .T only swap strides. The data isn't moved, so the tensor becomes non-contiguous and view will refuse it.
  • .contiguous() copies into a fresh, ordered block; reshape does that automatically when it must.

Who shares memory with whom? Must-know

Assignment, views, slices, detach() and numpy() all share memory with the original. clone(), torch.tensor(...), .contiguous() on a non-contiguous tensor and moving to another device copy. In-place operations (methods ending in _) modify shared memory — and everything aliasing it.

Devices

A tensor lives on one device. Operations need all inputs on the same device, and moving data between CPU and GPU is a copy across the PCIe bus — do it once per batch, not inside inner loops.
