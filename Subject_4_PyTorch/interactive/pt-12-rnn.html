MODULE 12 · SEQUENCES

Recurrent networks & a QA system

Text and time series are sequences: order matters and length varies. An RNN reads one step at a time and carries a hidden state forward. Here you build the whole text pipeline — tokens, vocabulary, embeddings, RNN — and wire it into a small question-answering model.

Concept

nn.Embedding is a trainable lookup table Must-know

nn.Embedding(num_embeddings, embedding_dim) holds a weight matrix of shape (vocab_size, dim). Feeding ids returns the matching rows: input (N, L) long → output (N, L, dim). Rows are updated by backprop like any weight, so words used in similar contexts drift close together.

One cell, reused at every time step Must-know

hₜ = tanh(Wih·xₜ + bih + Whh·hₜ₋₁ + bhh). The hidden state is the network's memory of everything read so far. "Unrolling" draws the same cell once per step; backprop through that unrolled graph is backpropagation through time (BPTT).

Concept

A question-answering model as classification

For a small factual dataset with one-word answers, treat the answer as a class from the vocabulary: Embedding → RNN → take the final hidden state → Linear(hidden, vocab_size) → CrossEntropyLoss against the answer's id. It memorises its training facts and shows the full sequence pipeline; real QA systems use transformers and retrieval, but the plumbing is the same.

"what is the capital of france"tokenise + encode → ids (1, 6)
nn.Embedding(V, 50)(1, 6) → (1, 6, 50)
nn.RNN(50, 64, batch_first=True)output (1, 6, 64), hidden (1, 1, 64)
hidden.squeeze(0) → nn.Linear(64, V)(1, V) logits over every vocabulary word
argmax → id → word"paris" (and softmax max as a confidence threshold)
