A tensor library with automatic differentiation Must-know

At its core PyTorch is two ideas: tensors — NumPy-like arrays that can run on a GPU — and autograd — a system that records operations on those tensors and computes gradients automatically.

Everything else is built on top of those two pieces: torch.nn gives you layers and losses, torch.optim gives you optimizers, and torch.utils.data streams batches of data. Because a model is just a Python class and the forward pass is just a Python function, you debug it like any other Python code.

Pythonic & eagerOperations run immediately. print(x.shape) anywhere, step through with a debugger.
GPU acceleration.to("cuda") moves tensors and models to NVIDIA GPUs; "mps" on Apple silicon.
AutogradCall loss.backward() and every parameter gets its gradient — no calculus by hand.
Dynamic graphsThe graph is rebuilt every forward pass, so loops and if-statements just work.
Research → productiontorch.compile, ONNX export, distributed training (DDP, FSDP).
Huge ecosystemtorchvision, Hugging Face, Lightning, Optuna — most new models ship in PyTorch first.

Define-by-run: the graph is your Python code Must-know

To compute gradients, a framework needs a computation graph: nodes are operations, edges are tensors flowing between them. The question is when that graph is built.

Static (define-then-run)
Build the whole graph first, compile it, then push data through. Easy to optimise ahead of time, but control flow needs special ops (tf.cond, tf.while_loop) and errors surface far from your code. TensorFlow 1.x worked this way.
Dynamic (define-by-run)
The graph is recorded as the code runs and thrown away after backward(). Every forward pass can take a different path. This is PyTorch's model — and the reason RNNs over variable-length sentences feel natural.

PyTorch vs TensorFlow in 2026 Must-know

The famous "dynamic vs static" split no longer holds — TensorFlow 2 is eager by default and PyTorch 2 compiles. What differs is style and ecosystem.

AspectPyTorchTensorFlow / Keras
ExecutionEager by default; torch.compile for speedEager by default; tf.function builds graphs
Training loopYou write it (full control), or use LightningUsually model.fit() via Keras
DebuggingStandard Python debugger, prints anywhereEasy in eager; harder inside tf.function
Research shareDominant; most new papers and Hugging Face modelsSmaller and shrinking

Same model, two frameworks
Notice what PyTorch makes explicit: the forward pass, the loss, clearing gradients, back-propagation and the update. That is more code, but nothing is hidden — and it is exactly what interviewers ask you to write.
