Save the state_dict, not the object Must-know

A state_dict is an ordered dictionary from names to tensors: every parameter (weights, biases) and every buffer (BatchNorm's running mean/var). It's plain data, so it survives refactors. For inference you need only the model's state_dict; to resume training you also need the optimizer's (Adam's moment estimates), the scheduler's and the epoch.

Concept

Randomness lives in many places Must-know

Weight initialisation, dropout masks, data shuffling, augmentation and some GPU kernels are all random. Python's random, NumPy and PyTorch each have their own generator; DataLoader workers get their own seeds too. Seed them all and request deterministic algorithms to make a run repeatable on the same hardware and library versions.

Concept

Half the bits, roughly twice the speed

Modern GPUs have tensor cores that multiply 16-bit floats much faster than 32-bit ones, and 16-bit tensors use half the memory. torch.autocast runs matmuls and convolutions in 16-bit while keeping sensitive ops (softmax, losses, reductions) in float32. The catch is range: float16's smallest normal number is about 6×10⁻⁵, so tiny gradients underflow to zero — GradScaler multiplies the loss up before backward and divides the gradients back down. bfloat16 keeps float32's exponent range, so it needs no scaler.

Concept

One line, same code, faster kernels

torch.compile(model) (PyTorch 2.0+) captures your forward pass as graphs with TorchDynamo, then TorchInductor fuses chains of small operations into fewer, larger GPU kernels (via Triton) or optimised C++ on CPU. Fewer kernel launches and fewer round-trips to memory = speed.

first call
Slow — tracing and compilation (seconds to minutes).
later calls
Fast — reuses the compiled code while input shapes and types stay the same.
graph break
Something Dynamo can't trace (e.g. print, data-dependent Python control flow, unsupported libraries) splits the graph; that part runs eagerly. Correct, but less speed-up.
recompile
New input shapes trigger recompilation; dynamic=True generalises over shapes.
mode=
"default", "reduce-overhead" (CUDA graphs, small batches), "max-autotune" (longest compile, fastest kernels).
