nn.Module, losses & optimizers

The three abstractions that turn the from-scratch loop into idiomatic PyTorch: nn.Module to hold layers and parameters, torch.nn losses to measure error, and torch.optim to update weights.

nn.Module: a class that knows its parameters Must-know

Subclass nn.Module, call super().__init__(), assign layers as attributes in __init__, and describe the computation in forward. Because the layers are attributes, PyTorch registers their weights automatically — so model.parameters(), model.to(device), model.eval() and model.state_dict() all just work.

nn.Linear(in, out)
y = xWᵀ + b. Weight shape (out, in), bias (out,); in·out + out parameters.
nn.ReLU / Sigmoid / Tanh / GELU
Activations — no parameters. Without them, stacked Linear layers collapse into one linear map.
nn.Sequential(...)
Chains modules in order; perfect for straight pipelines.
nn.ModuleList / ModuleDict
Containers that register sub-modules — never use a plain Python list. Must-know

Same gradients, different update rules Must-know

SGD
w ← w − lr·g. Zig-zags across narrow valleys.
SGD + momentum
v ← βv + g; w ← w − lr·v. Builds speed along consistent directions, damps oscillation.
RMSprop
Divides each parameter's step by the running RMS of its gradients — equalises step sizes.
Adam
Momentum + RMSprop + bias correction. Robust default, lr=1e-3.
AdamW
Adam with decoupled weight decay — the standard for transformers.
