MODULE 09 · BUILDING NETWORKS

Hyperparameter tuning with Optuna

Learning rate, layer sizes, dropout, batch size, optimizer — none of these are learned by gradient descent. Optuna searches them for you, learns which regions look promising, and kills bad trials early.

Three ways to spend the same budget Must-know

The landscape below is a validation-accuracy surface over learning rate (x, log scale — matters a lot) and dropout (y — matters a little). Each method gets the same number of trials.

  • Grid tests only √n distinct learning rates — and wastes trials re-testing dropout values that barely matter.
  • Random tests n distinct learning rates, so it finds the good band more often.
  • TPE (Optuna's default sampler) starts randomly, then samples more where good trials were — exploiting what it learned.

Concept

Objective → trial → study

objective(trial)
Samples hyperparameters, builds and trains a model, returns the validation metric.
trial.suggest_float / int / categorical
Defines the search space as the code runs — so it can be conditional (e.g. number of units per layer depends on number of layers).
optuna.create_study(direction=…)
"maximize" for accuracy, "minimize" for loss.
trial.report + should_prune
Report the metric each epoch; the pruner stops hopeless trials early.
Try it · median pruning
warm-up epochs before pruning (n_warmup_steps)

A trial is pruned when its accuracy at an epoch is below the median of earlier trials at that same epoch.
