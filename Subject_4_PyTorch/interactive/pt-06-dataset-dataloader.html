Dataset & DataLoader

A Dataset answers two questions — how many samples, and what is sample i? A DataLoader turns that into shuffled, batched, parallel-loaded tensors. Together they decouple "where data comes from" from "how the model trains".

Two methods: __len__ and __getitem__ Must-know

Subclass torch.utils.data.Dataset. In __init__, load the cheap stuff (a dataframe, a list of file paths). In __getitem__(idx), do the per-sample work — read the image, apply transforms, convert to tensors — and return one sample. Lazy loading keeps memory low and lets DataLoader workers do the work in parallel.

DataLoader = sampler + batching + collate + workers Must-know

Each epoch the DataLoader asks a sampler for an order of indices (shuffled or sequential), groups them into batches of batch_size, calls dataset[i] for each index (in worker processes if num_workers > 0), and stacks the samples into batch tensors with collate_fn.

When samples don't have the same shape Must-know

The default collate_fn calls torch.stack, which needs equal shapes. Sentences have different lengths, so stacking fails with "stack expects each tensor to be equal size". A custom collate_fn pads each batch to its own longest sequence — cheaper than padding the whole dataset to the global maximum — and returns the true lengths.

Controlling order and throughput

A sampler decides which indices are drawn and in what order. WeightedRandomSampler oversamples rare classes so each batch is roughly balanced. Workers load the next batches in background processes while the GPU trains on the current one.
