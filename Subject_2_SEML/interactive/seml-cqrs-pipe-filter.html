ConceptsWhat to remember

CQS → CQRS

Bertrand Meyer's Command-Query Separation: a method either changes state (command) or returns data (query), never both. Greg Young applied it at system scale as CQRS: separate write and read models — often separate stores — so each scales and evolves independently.

Pipe-and-filter

Data streams through pipes into independent filters that each do one transformation. Filters are reusable and replaceable — swap the embedding model or chunker without touching the rest — and can run concurrently.

Trade-off

CQRS adds complexity and eventual consistency: a new document becomes searchable only after replication. Worth it when reads and writes have very different load (e.g. a flash-sale where one locked database fails under both).

Demo-scale retrieval: 64-dimensional hashed bag-of-words “embeddings”, chunks of ~25 words with 5-word overlap (production systems typically use ~300 tokens with ~50 overlap and a learned embedding model).
