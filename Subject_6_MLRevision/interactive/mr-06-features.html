MODULE 06 · DATA

Data & feature engineering

Better features beat better models. These are the data questions that show up in almost every ML round: what to do with missing values, how to encode categories, which models need scaling, and how to treat outliers and skewed features — always fitting the transformation on training data only.

Concept

First ask why it is missing Must-know

MCAR (completely at random — a sensor glitch): dropping or simple imputation is unbiased. MAR (depends on observed features — older users skip a field): impute from other features (KNN, iterative/model-based). MNAR (depends on the missing value itself — high earners hide income): every imputation is biased; the fact of missingness is informative, so add a missing-indicator feature. Mean imputation also shrinks variance and weakens correlations. Tree boosters (XGBoost, LightGBM) can route missing values natively.

Concept

Match the encoding to the cardinality and the model Must-know

One-hot: one column per category — safe for linear models, explodes with high cardinality. Label/ordinal: integers — only meaningful for ordered categories (or tree models). Target (mean) encoding: replace a category by the average label — compact and powerful for high cardinality, but leaks the label unless done out-of-fold with smoothing. Hashing: hash into a fixed number of columns — handles unseen categories and huge vocabularies, with collisions. Embeddings: learned dense vectors (deep models, IDs in recommenders).

Concept

Scale when the model uses distances, dot products or gradients Must-know

\( \text{standard: } \frac{x-\mu}{\sigma} \qquad \text{min-max: } \frac{x-\min}{\max-\min} \qquad \text{robust: } \frac{x-\text{median}}{\text{IQR}} \)

k-NN, k-means, SVM, PCA and regularized linear models compare feature magnitudes; neural nets and gradient descent converge faster on similar scales. Tree models split on thresholds, so monotonic scaling changes nothing. Min-max squeezes everything into [0, 1] but one outlier compresses the rest; robust scaling uses median and IQR to ignore it.

Concept

Detect, understand, then decide

Detect with the IQR rule (outside Q1 − 1.5·IQR or Q3 + 1.5·IQR), z-scores (|z| > 3, assumes roughly normal data), or model-based methods (Isolation Forest, LOF). Then ask whether it is an error (fix or drop) or a real rare event (keep — in fraud it is the signal). Options: cap/winsorize, transform (log, Box-Cox, Yeo-Johnson), robust losses (Huber, MAE) and robust models (trees). For right-skewed features (income, prices, counts), a log transform makes the distribution more symmetric and relationships more linear.
