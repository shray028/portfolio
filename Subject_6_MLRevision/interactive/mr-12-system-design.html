Decide the metric, the effect size and the duration before you start Must-know

\( n_{\text{per arm}} \approx \frac{(z_{1-\alpha/2}+z_{1-\beta})^2\,[p_1(1-p_1)+p_2(1-p_2)]}{(p_2-p_1)^2} \)

Randomise users (not requests) into control and treatment, pick one primary metric plus guardrails (latency, errors, returns, revenue), compute the sample size for the smallest effect worth detecting (MDE), run for whole weeks to cover weekly cycles, and don't stop early when the p-value dips below 0.05 ("peeking" inflates false positives). Watch for novelty effects, sample-ratio mismatch, and interference between groups (shared inventory, marketplaces, in-store staff).

Concept

"Offline NDCG went up, online conversion went down." Must-know

Offline metrics are computed on logged data generated by the old system, with a proxy label, without latency, and frozen in time. Online metrics measure real behaviour under the new system. They disagree for predictable reasons; investigate from cheapest-to-verify to deepest: experiment validity → serving correctness → system effects → objective mismatch. Concept

Data drift, concept drift, and bugs that look like drift Must-know

Data (covariate) drift: the input distribution changes (new users, new products, a marketing campaign). Concept drift: the relationship between inputs and the label changes (fraudsters adapt, a pandemic changes buying). Label/prior shift: the base rate changes. But first rule out pipeline bugs — a feature silently null, a unit change, a schema change — which cause most "drift". Monitor three layers: system health (latency, errors), data health (schema, nulls, feature distributions — PSI, KS), and model/business outcomes (prediction distribution, delayed-label performance, KPIs). The Population Stability Index compares binned distributions:

\( \text{PSI}=\sum_{b}\big(a_b-e_b\big)\ln\frac{a_b}{e_b},\qquad <0.1 \text{ stable},\ 0.1\text{–}0.25 \text{ moderate},\ >0.25 \text{ significant} \)
