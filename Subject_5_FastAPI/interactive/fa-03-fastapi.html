What is FastAPI?

FastAPI's name carries two promises: fast to run and fast to code. The first comes from ASGI, Starlette and Uvicorn; the second from type hints and Pydantic. This module shows exactly which layer does what — and when "async" helps and when it doesn't.

Concept

Fast to run

  • Built on Starlette, an async web toolkit
  • Served by Uvicorn, an ASGI server
  • async/await: one process juggles thousands of waiting connections
  • Benchmarks close to Node.js and Go frameworks

Fast to code

  • Type hints drive parsing, validation and docs
  • Pydantic validates input automatically
  • Free interactive docs at /docs and /redoc
  • Less boilerplate, fewer bugs, great autocomplete

One worker, many waiting requests Must-know

WSGI (Flask, classic Django) is synchronous: a worker handles one request at a time and sits idle while it waits on a database, disk or another API. ASGI (FastAPI) runs an event loop: while one request waits on I/O, the worker switches to another.

ASGI does not make CPU-heavy code faster. The event loop only helps while you are waiting. A big model.predict keeps the CPU busy; inside an async def, nothing else can run meanwhile. Set the I/O wait to 0 below to see the advantage vanish.
