Path & query parameters

From here the course builds one CRUD API for a doctor — the Patient Management System, backed by patients.json. Path parameters pick a patient; query parameters sort the list; HTTPException handles what isn't there.

Concept

Same name in braces and in the signature → injected Must-know

A path parameter is a variable segment of the URL in curly braces. FastAPI matches the name to the function argument of the same name and converts it to the annotated type. Path() adds metadata and validation:

...
required (path params always are)
title, description
shown in /docs
examples=["P001"]
example value in /docs — example= is deprecated
gt ge lt le
numeric bounds
min_length max_length
string length bounds
pattern=r"^P\d{3}$"
regex — the old regex= is deprecated

HTTPException: raise HTTPException(status_code=404, detail="Patient not found") stops the function and returns 404 {"detail": "Patient not found"}. You raise it, not return it.

Concept

Not in the path + simple type = query parameter Must-know

Any argument that isn't in the path template and has a simple type (str, int, bool, Literal…) is read from the query string. Give it a default and it becomes optional. Query() adds the same metadata and constraints as Path().

The course's /sort validated sort_by and order by hand (400) — and had the sort direction backwards. The cleaner version uses Literal, deletes both ifs, returns 422 automatically and gives /docs a dropdown.

FastAPI reads your signature Must-know

  1. Is {x} in the path template? → path
  2. Is the type a Pydantic model? → body (JSON)
  3. Wrapped in Header(), Cookie(), Body() or Depends()? → that source
  4. Otherwise → query
