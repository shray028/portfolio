HTTP essentials

FastAPI is "just" a nice way to speak HTTP, so the vocabulary needs to be automatic: what each part of a URL means, what a request and a response carry, which methods are safe or idempotent, and which status code to return when.

Concept

Path identifies, query modifies

  • Path parameter — part of the path itself; identifies which resource: /patient/P001.
  • Query parameters — optional knobs after ?, as key=value pairs joined by &; how you want it (sort, filter, paginate).

Concept

4xx: the client should change the request. 5xx: the server is at fault. Must-know

2xx Success
  • 200 OK — GET/PUT success with a body
  • 201 Created — POST created something (/create)
  • 204 No Content — success, empty body (typical for DELETE)
3xx Redirect
  • 307 Temporary Redirect — FastAPI redirects /items/ ↔ /items
4xx Client
  • 400 Bad Request — valid shape, breaks your rule (invalid sort field)
  • 401 Unauthorized — who are you? (missing/bad credentials)
  • 403 Forbidden — I know you, but you may not do this
  • 404 Not Found — unknown patient id
  • 405 Method Not Allowed — POST to a GET-only route
  • 409 Conflict — clashes with current state (patient exists)
  • 422 Unprocessable Content — FastAPI/Pydantic validation failed
  • 429 Too Many Requests — rate-limited
5xx Server
  • 500 Internal Server Error — unhandled exception in your code
  • 503 Service Unavailable — not ready, e.g. model not loaded
