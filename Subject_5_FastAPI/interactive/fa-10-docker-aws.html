Docker & AWS EC2

"It works on my machine" stops being an excuse. Docker packages Python, pinned libraries (a pickle from scikit-learn 1.6.1 may not load in another version) and OS packages into one image. The course then pushes that image to Docker Hub and runs it on an EC2 instance.

Concept

Image vs container Must-know

A Dockerfile is the recipe. docker build turns it into an image: a read-only template, like a class. docker run starts a container: a running instance, like an object — you can run many from one image. Images are shared through a registry (Docker Hub, ECR) with push / pull.

Containers vs virtual machines

A VM virtualises hardware and boots a full guest OS: gigabytes, minutes to start. A container shares the host's kernel and packages only the app and its libraries: megabytes, seconds to start. Same isolation goal, much lighter.

Concept

-p HOST:CONTAINER and --host 0.0.0.0 Must-know

A container has its own network interface. -p 80:8000 forwards traffic arriving on the host's port 80 to the container's port 8000. That traffic arrives on the container's external interface, so uvicorn must listen on all interfaces (0.0.0.0). The default 127.0.0.1 only accepts connections from inside the container itself. EXPOSE is documentation; it publishes nothing.
