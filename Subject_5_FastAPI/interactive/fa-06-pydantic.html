Pydantic: the data guard

The most-asked FastAPI topic is really a Pydantic topic. Declare the ideal schema once; every request is validated, coerced, documented and serialised from it. This module lets you feed data into real course models and watch exactly what Pydantic does.

Concept

Type hints are documentation, not enforcement Must-know

Python is dynamically typed: insert_patient_data("Shray", "Twenty seven") runs happily with age: int in the signature, and garbage reaches the database.

1. Type hints onlyReadable, but nothing is checked.
2. Manual if type(x) != ...Works, but repeated in every function — doesn't scale.
3. Pydantic modelDeclare once; validation + coercion everywhere.

The three-step workflow

  1. Define a class inheriting BaseModel — the ideal schema.
  2. Instantiate with raw data: Patient(**raw_dict) — validates and coerces, or raises ValidationError.
  3. Use the validated object; every function can trust p.age is an int.

The validation pipeline Must-know

When you call Patient(**data) things happen in a fixed order: before validators see the raw value → type check and coercion → Field constraints → after validators see the clean typed value → model validators see all fields → computed fields are evaluated on access. Any failure raises ValidationError (422 in FastAPI).

Derived values that still appear in the output Must-know

@computed_field + @property: a value computed from other fields that the client never sends but that appears in model_dump(), JSON responses and /docs. @property lets you write p.bmi; @computed_field includes it in serialisation and the schema; the return type hint is required. Computed fields can use other computed fields — verdict reads bmi.

Nested models and model_dump Must-know

A model can be a field type: address: Address. A plain dict is converted automatically and validated all the way down; errors report the full location, e.g. ("address", "pin_code"). Going the other way, .model_dump() gives a dict (computed fields included) and .model_dump_json() a JSON string.

  • exclude for a nested field is a dict that mirrors the tree: {"address": {"state"}}.
  • exclude_unset=True dumps only fields the caller actually provided — the hero of partial updates (module 07).
