Concept

Separation of concerns: each layer changes for one reason

app.py holds thin routes. schema/ says what data looks like. model/ says how predictions are made and is the only place that knows about pickle and pandas. config/ holds constants. The front-end is a separate client that only speaks HTTP. Swap the model and app.py doesn't change; add a field and only schema/ changes.

Concept

/ is for humans, /health is for machines Must-know

Load balancers and Kubernetes poll /health to decide where traffic goes. Liveness asks "is the process alive?" — if not, restart it. Readiness asks "can it serve right now?" — model loaded, DB connected — if not, don't send requests yet. For an ML service, report model_loaded and the model version so you can verify a deploy.

Concept

response_model validates, filters and documents your output Must-know

Returning a dict or model lets FastAPI run it through response_model: a wrong shape becomes a loud 500 instead of silent garbage, extra fields (a password hash, debug info) are dropped, and /docs shows the schema. Returning a JSONResponse yourself skips all three.

Concept

Every failure gets a deliberate status code

Bad input is a 422 for free. Known business failures raise HTTPException with 400/404/409. A model that isn't loaded yet is a 503. Anything unexpected is logged with the stack trace on the server and returned as a generic 500 — never str(e), which leaks file paths, SQL and library internals.
