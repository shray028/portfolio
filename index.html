How I think about AI systems

[01]

Deterministic first, LLM last

If a rule, a template or a graph lookup can answer, it should. The model handles what is left, and its output is checked before anyone sees it.

[02]

Grounded or it doesn't ship

Answers cite the spec they came from, and generated XML is validated against the schema. A confident wrong answer costs engineers more than no answer.

[03]

Measure, then trust

Retrieval hit rates, answer checks and regression suites run before every change, so "it feels better" becomes a number.

[04]

Adoption is the metric

A tool only counts when engineers use it every week. It has to fit the workflow they already have, not ask them to learn a new one.

Three systems behind one result

How a plain-language change request becomes a validated ARXML edit. Highlighted boxes are the parts I designed and built; dashed ones are platforms and sources I build on.

Agentic RAG · Production

Change-request agent

5 minper change request, down from 2–3 days

Engineers describe an AUTOSAR change in plain language. The agent finds the affected elements in the knowledge graph, drafts the ARXML edit and runs it through schema guards before handing it back. I chose graph retrieval with schema guards over a single LLM call, so every edit is traceable and no hallucinated XML reaches a file.

What made it hard
  • The metamodel is deep, and references cross files.
  • One invalid element can break an ECU build, so "mostly right" isn't good enough.
  • Engineers need to see why something changed, not just the diff.

Engineering assistants

1,000+queries a week from 100+ engineers

Assistants that answer questions about specs, tools and processes from internal documents, with sources attached, plus automation for repetitive configuration steps. Built so engineers can check an answer in seconds instead of searching for it.

  • Documents are long and full of tables and IDs that plain embeddings handle badly.
  • Answers have to stay right as documents change.
  • Trust is earned one cited answer at a time.

Data layer · Knowledge graph

AUTOSAR knowledge graph

551metamodel classes parsed from 270 UML diagrams

A streaming, two-pass parser turns ARXML and UML into an object model with references in both directions. That model becomes the graph the agent queries, so retrieval follows real relationships instead of text similarity alone.

What made it hard
  • Files are large, so the parser streams instead of loading everything into memory.
  • References point forwards and backwards; a second pass resolves them.
  • The graph has to match the official metamodel exactly.
